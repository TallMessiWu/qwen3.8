Qwen3.5-35B · KV cache 量化

C8 的两套配方

两份权重的目录名都带 c8，KV cache 也都量化成 fp8 e4m3。但它们走的是两套互不相通的 scale 体系，由 quant_model_description.json 里的一个键决定，而 QFA 只认其中一套。

分叉点

框架读 description 顶层键来选配方。两份权重在这里就分开了，后面所有差异都是这一步的结果。

Qwen3.5-35B-A3B-mxfp4-c8
"kv_cache_type": "K_DYNAMIC_V_STATIC_MXFP8_PER_CHANNEL"
"fa_quant_type": 不存在

走 MXFP8 C8。modelslim_config.py:1121 置 enable_mxfp_c8_quant。

qwen3_6_35b_a3b_w8a8_mxfp8_c8_fix_mtp
"kv_cache_type": 空
"fa_quant_type": "FAKQuant"

走 FAKQuant。modelslim_config.py:1116 置 enable_fa_quant。

量化策略

两者的存储格式一样（A5 上都是 fp8 e4m3），差别全在 scale 怎么算、存哪、多细。

维度 MXFP8 C8（旧） FAKQuant（新）
K 的 scale 动态，每步现算沿 head_dim 每 32 元素一个 E8M0 指数 静态，读 checkpoint每个 KV head 一个浮点 scale
V 的 scale 静态 per-channel E8M0加载后广播进 cache，之后不再写 静态 per-head scale与 K 同一套机制
offset 无E8M0 是 2 的幂，对称量化不需要 有非对称仿射量化，K/V 各一份
scale 粒度 512 个 / 层= kv_heads 2 × head_dim 256 2 个 / 层= kv_heads，粗 256 倍
scale 存哪 cache 里的独立平面与 K/V 同页，随数据一起读 层参数里cache 中没有 scale 平面
QFA 能读 能 不能kernel 直接消费 cache 里的 scale 平面，这套没有

结论

新权重不是「没做 KV cache 量化」——它做了，只是做成了 QFA 读不了的布局。这不是权重缺东西，是量化配方选错了。

它也当不了 bf16 基线：既走 FAKQuant 的 fp8 cache 而非 bf16，模型版本（qwen3_6 / 3.5）和 linear 配方（w8a8_mxfp8 / mxfp4）又都变了。干净的基线仍是同一份旧权重加 C8=0。

fix_mtp 是真修复，但修的是 MTP 主干的 linear 量化，与 KV cache 无关；MTP 的 KV cache 在两份权重里都仍未覆盖。

要一份能跑 QFA 的权重，需要说明

  • KV cache 按 dynamic_cache 量化，scope per_channel、dtype mxfp8
  • 产出顶层 "kv_cache_type": "K_DYNAMIC_V_STATIC_MXFP8_PER_CHANNEL"
  • 每个全注意力层带 v_proj.v_scale，[kv_heads × head_dim, 1] uint8
  • 不要 fa_quant_type / fa_*.scale / fa_*.offset（那会抢先并让 QFA 失效）
  • 若能把 mtp. 前缀纳入 KV cache 量化范围，可回收 draft 的接受率
