## 第三次踩坑：gate/up 切分轴错误（2026-08-29）

现象：加载到 `RoutedExperts._load_w13` 崩，`Target sizes: [2048, 8192]. Tensor sizes: [4096, 4096]`。

| | BF16 原权重 `/mnt/share/weight/Qwen3.8-2.4T-A95B` | mxfp8 |
| --- | --- | --- |
| routed experts | `experts.gate_up_proj` `[512, 4096, 8192]`（3D 融合） | `experts.N.gate_proj`/`up_proj.weight` 各 `[4096, 4096]` |

单专家融合张量是 `[4096, 8192]`，`4096 = 2 × moe_intermediate(2048)`——gate/up 在 dim0，hidden 在 dim1。正确拆法是 `chunk(2, dim=0)` → 两个 `[2048, 8192]`；实际拿到两个 `[4096, 4096]`，即 `chunk(2, dim=1)`，**沿 hidden 轴切的**。vLLM 处理 3D 融合张量时用的正是 `chunk(2, dim=1)`（`routed_experts.py`，`[E, 2I, H]` 里 dim1 才是 gate/up 轴），导出脚本很像照搬了这一行、降成 per-expert 2D 后没把轴号改成 0。

字节级已确认（`scripts/debug/verify_expert_split_axis.py`，比符号平面不需反量化）：`gate_proj` vs `fused[:, :4096]` 符号一致率 100%，vs `fused[:, 4096:]` 49.8%；`up_proj` 反之。所以每个 `gate_proj` 文件装的是 **gate 和 up 各自的前半段 hidden**，加载侧无法单独还原。

佐证：`down_proj` `[8192, 2048]` 完全正确，`shared_expert.gate_proj.weight_scale` `[2048, 256]`（256×32=8192）说明正确的 gate 就该是 `[2048, 8192]`——同一份权重里只有 routed expert 走了坏路径；scale 按错误布局算（`gate_proj.weight_scale [4096,128]`），说明量化在错误切分之后执行。

**数据无损，不必重新量化**：`concat([gate,up], dim=1)` 拼回 `[4096, 8192]` 再 `chunk(2, dim=0)`；scale 同样 concat dim1 → `[4096,256]` 再切 dim0 → `[2048,256]`（正好等于 shared expert 的 scale 形状）。MX block 沿最后一维 32 个元素，4096/128 都是整块数，拼切不跨 block 边界，纯搬字节即可。

## 格式事实

- BF16 原权重用 **transformers 5.x fused expert 布局**：`model.layers.N.mlp.experts.gate_up_proj` / `.down_proj`（裸键、无 `.weight` 后缀、512 expert 堆叠 3D），vLLM 靠 `is_fused = loaded_weight.dim() == 3` 原生支持。mxfp8 侧则是 per-expert 2D 键。
- config: `model_type='qwen3_5_moe_text'`、92 层（69 linear_attention + 23 full_attention）、512 experts、hidden 8192、moe_intermediate 2048、head_dim 256、vocab 248320。

**Why:** 32 卡装不下 BF16 全量，量化是必选项；三次挫折依次是"芯片代次选错"（A3 int8）、"量化未真正执行"（BF16 占位）、"量化执行了但拆分轴错"，全在权重侧，没有一次是 vLLM/vllm-ascend 代码的问题。

**How to apply:** 这套脚本报权重相关错误时，先跑离线诊断再读代码，顺序是
「打印 quant description 实况 → 与 BF16 原权重比形状（路径去掉 `-mxfp8` 后缀，脚本
[`compare_checkpoint_shapes.py`](../../scripts/checks/compare_checkpoint_shapes.py) 还在）
→ 字节级定轴」。当年做前两步与第三步的两个脚本（`check_quant_desc_qwen35_moe_text.py`、
`verify_expert_split_axis.py`）都按 `AGENTS.md` 约束 3 结案后删掉了，需要时按本节写的方法重写：
第一、二步是读 `quant_model_description.json` 的 dtype 与逐张量比形状；
第三步是**比符号平面而不需反量化**——拿 `gate_proj` 与 `fused[:, :4096]` / `fused[:, 4096:]`
各算一次符号一致率，100% / 49.8% 这种差值一眼定轴。
永远不要默认权重目录名可信。判断形状问题时**必须比 numel 而不只是某一维**：
`4096×4096 == 2048×8192`，只看行数会误判成 gate/up 融合。
数据搬运约束见 技能 `vendor-ascend-op` 的「数据搬运」。
